# 总体计划

## 1. 任务来源

`agent.md` 定义四项任务，本计划把四项任务拆成可独立验证、可独立回滚的阶段，并
规定每一项的完成判定。计划只描述要达成的行为，不描述代码结构；代码层面的取舍
写在 `design/`。

| 阶段 | 任务 | 目标一句话 |
| --- | --- | --- |
| A | 任务 1 | 输入改为"无输入则不唤醒"的等待模型，每个输入源一个线程，线程拥有自己的输入缓冲与状态 |
| B | 任务 2 | 实现 `GetConsoleWindow`：不可见伪窗口，独立线程，融入 A 的等待模型 |
| C | 任务 3 | defterm 模式的自动化测试库与测试集 |
| D | 任务 4 | conpty 模式的自动化测试库与测试集（含 ssh、vim/edit、powershell/cmd、继承控制台） |

## 2. 不可协商的约束

这些约束来自 `agent.md`，任何实现方案都必须同时满足，不因为"更方便"而豁免。

| 约束 | 判定方式 |
| --- | --- |
| 不轮询：没有输入时线程不唤醒 | 审查等待路径，不允许以固定短超时反复唤醒主循环；用空闲唤醒计数与 CPU 占用验证 |
| 每个输入源一个线程，线程拥有自己的输入缓冲与状态 | 状态归属表必须能逐项列出"谁写、谁读、如何同步" |
| 必须正确处理线程等待与退出，主线程等待所有线程结束 | 退出协议覆盖正常 EOF、对端断开、强制关闭三条路径；退出时 join 全部线程 |
| 区分可恢复错误与致命错误：系统函数本不应失败却失败、OOM 属致命 | 错误处理矩阵逐项列出；致命路径必须是异常或 `std::abort()`，不允许静默 |
| 每个可能返回错误的调用都必须检查 | 逐个调用点复核，禁止丢弃返回值 |
| 不捕获异常 | 全仓库不允许新增 `catch`；线程内致命错误用 `std::abort()`（异常不能跨线程） |
| 锁与条件变量使用 SRWLock | 只允许使用 `common/win32` 中的 SRWLock/CV 封装，禁止 `CRITICAL_SECTION`/`std::mutex` 新增使用 |
| 工作线程必须有不同命名 | 线程创建处显式设置线程名，运行时可区分 |
| 代码风格匹配现有代码，现代 C++，单一职责，优先清晰可靠 | 评审标准；不为了"聪明"牺牲可读性 |
| 禁止联网搜索 | 遇到困难记录到 board 后跳过，不允许联网查资料或下载依赖 |
| 所有测试必须能自动化执行 | `ctest` 一条命令可跑；人工步骤只能是可选增强 |
| 每完成一个子任务提交一次并记录状态 | commit 与 board 更新成对出现 |
| 设计取舍分文件记录在 `doc/` | 每个取舍一个 `design/` 文件或一节 |
| BUG 先开独立分支修复，删除无效代码后合并 | 见第 7 节 |

## 3. 阶段与依赖

```
阶段 0  文档骨架（本提交）
   |
   v
阶段 A  I/O 模型（A1 → A11）
   |
   v
阶段 B  伪窗口（B1 → B8）     依赖 A 的线程/队列/等待基础设施
   |
   +--> 阶段 C  defterm 测试（C1 → C6）   依赖 B（窗口消息用例）
   |
   +--> 阶段 D  conpty 测试（D1 → D6）    只依赖测试库骨架（C1），可与 C 并行
```

顺序理由：A 改变线程与唤醒结构，B 要在新结构上挂第四个输入源；先做 B 再做 C，
是因为 defterm 用例里"用 GetConsoleWindow 发消息"是核心交互手段。测试库骨架只在
C1 建一次，C、D 共用，避免两套测试风格。

## 4. 完成定义（DoD）

单个子任务完成必须同时满足：

1. 行为符合该子任务在 `plan/` 中的验收条目，且验收方式可重复执行。
2. 新增/修改的代码通过 `cmake --build build`，无新增编译警告（允许存在的既有
   警告需在同一提交中说明）。
3. 相关测试已加入 `ctest` 并能稳定通过；不能自动化的部分在 board 中标注原因。
4. `doc/` 中对应状态、设计结论已更新。
5. 一次提交，提交信息说明"做了什么 + 验收结论"。

整体完成（goal 完成）额外要求：

- 四项任务的验收清单全部勾选，且能在干净构建目录中从零配置、构建、测试通过。
- 空闲状态下主循环不因超时唤醒；会话退出无残留线程与句柄泄漏。
- `doc/` 的 board 中不存在 `DOING`/`BLOCKED` 项（阻塞项必须已解决或明确移出范围）。
- 规则检查：仓库中不存在联网依赖、`catch`、新增的非 SRWLock 锁。
- `agent.md` 的全部约束在第 2 节表格中逐条有对应证据。

## 5. 验证总纲

每个阶段结束至少执行：

```powershell
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DCOREHOST_DISABLE_LOG=OFF -DCOREHOST_LOG_LEVEL=2
cmake --build build
ctest --test-dir build --output-on-failure
```

- 日志级别按需使用 1/2/3；级别 1 只保留生命周期事件，级别 3 用于时序诊断。
- 涉及真实终端的用例（WindowsTerminal、ssh、vim/edit）必须有"环境探测 + 跳过"
  逻辑，跳过原因写入测试输出，不能被当成通过。
- 涉及唤醒/CPU 的验收，用固定方法测量并记录数值到 board，而不是"看起来正常"。

## 6. 风险登记

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | 把输入状态迁移到线程后行为回归（行编辑、Win32 Input、Ctrl+Z、CPR） | 高：用户可见功能损坏 | 先补现有行为测试锁定基线，再迁移；每步保持可构建 |
| R2 | 阻塞读无法被可靠取消 | 高：退出挂起 | 取消协议 + 无限 join；终止性由"停止标志 + 可取消读 + 取消重试"保证，不用超时兜底；见 `design/0001` |
| R3 | 死锁、丢失唤醒、事件误用 | 高：随机卡死 | 单一等待集、队列 + 自动重置事件的标准模式、锁序约定、压力测试 |
| R4 | 窗口线程与主线程时序（同步消息、销毁竞态） | 中 | 同步消息只在窗口线程完成；销毁前握手 |
| R5 | 测试环境依赖（WT 版本、sshd 服务、权限、前台窗口） | 中：CI 不稳定 | 环境探测与跳过、不修改系统全局设置、非交互驱动优先 |
| R6 | 任务规模大，单步过大导致不可回滚 | 中 | 子任务粒度控制在"一次提交可评审"；每步可构建 |

## 7. 工作方式

- 分支：正常开发在 `main`；修 BUG 使用 `bugfix/<slug>` 分支，修复并验证后删除
  调试代码、压缩提交，再合并回 `main`。
- 提交：一个子任务一次提交；提交信息包含子任务编号（如 `A4`），便于 board 对照。
- 文档顺序：先计划 → 再实现 → 再更新 board/design → 提交。禁止先写实现后补计划。
- 记录实现状态：board 只记"事实"（做了什么、验证结论、提交号），不写计划性描述。

## 8. 范围外

- 不实现通用的 conhost 兼容层，只覆盖 `GetConsoleWindow` 及其必要消息面。
- 不重构输出路径（VT 输出缓冲、渲染同步）——除非 A 阶段的线程化必须触及。
- 不引入第三方库、不联网下载测试框架。
- 不修改 `terminal/`（原版 conhost）源码，只读学习；不把它的实现照搬进 corehost。
- 不追求 `GetConsoleWindow` 支持完整的窗口 UI（菜单、滚动条、DPI 交互），只保证
  依赖它的程序能正常工作。
