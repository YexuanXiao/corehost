# Window Mode 实施计划

本文只描述目标、边界、任务和验收标准，不描述具体代码结构。代码实现阶段再按现有模块接口进行调整。

## 目标

为 corehost 增加真正的窗口模式：

- 新建 `corehostw` 可执行目标；
- 与 `corehost` 共享 `corehost/cli/main.cpp`；
- 通过编译宏切换入口；
- `corehostw` 调用 `window_entry`；
- `window_entry` 在 corehost 进程内维持控制台并显示终端窗口；
- 不使用 ConPTY；
- 不使用 `libconpty`、`libcorepty`；
- 不使用 `defterm` 目录下的代码；
- 使用现有 `libconsole`、`libcoreio`、`libinterop`、`libscreen`、`libvtparser`、`libvtstate`、`common`；
- GUI 规格以 `terminal-window-plan.md` 为准；
- Windows 11 22000+；
- C++23、现代 C++、C++/WinRT 操作 COM；
- 禁止可变全局变量、lambda、`std::mutex`、虚函数（COM 除外）；
- 所有状态通过参数传递；
- 每个模块单一职责；
- 每个子任务完成后提交并更新状态文档；
- 所有可自动化测试必须能在 CI 运行。

## 约束与已确认事实

- `corehost` 当前由 ConDrv 以 conhost 模式启动时，命令行携带一个 ConDrv `\Server` 句柄。
- `client_entry` 只负责 `CreateProcess(CREATE_NEW_CONSOLE)`，它本身不持有控制台服务器句柄。
- 一个进程要在自身内部实现完整控制台，必须持有 ConDrv `\Server` 句柄并处理 `CONNECT`。
- 因此 `window_entry` 的“参数与 `client_entry` 相同”与“在 corehost 进程内维持控制台”存在结构性冲突；该冲突单独记录在 `0002-launch-contract.md`。

## 阶段与子任务

### W0：文档与启动契约

- W0.1 建立本计划、模块边界、状态文档；
- W0.2 明确 `window_entry` 的控制台服务器来源；
- W0.3 明确 `corehostw` 的启动方式和注册方式；
- W0.4 确定 `window_entry` 与 main 的宏切换方式。

验收：

- 启动契约没有未决歧义；
- 不引入与“单进程、无 ConPTY”矛盾的路径。

### W1：corehostw 目标与入口骨架

- W1.1 增加 `corehostw` CMake target；
- W1.2 复用 `corehost/cli/main.cpp`；
- W1.3 编译宏切换 `client_entry` / `window_entry`；
- W1.4 保证 `corehost` 的目标、资源和链接不变；
- W1.5 `corehostw` 和 `corehost` 一样保留 defterm、comserver、headless/ConPTY 启动路径；只有普通 client 启动路径切换为 `window_entry`；
- W1.6 添加自动化构建测试和入口 smoke test。

验收：

- `corehost` 与 `corehostw` 均可单独构建；
- `corehostw` 不产生 defterm/libcorepty 依赖；
- main 只有一个源文件。

### W2：窗口宿主最小闭环

- W2.1 注册并创建 top-level Win32 窗口；
- W2.2 建立消息循环；
- W2.3 处理关闭、DPI、尺寸、焦点；
- W2.4 空闲时阻塞，不轮询；
- W2.5 建立 `libcorewindow` 宿主骨架；
- W2.6 窗口启动过程可测试。

验收：

- `corehostw` 打开空白窗口；
- 关闭窗口后进程正常退出；
- 失焦或光标不闪烁时空闲 CPU 为 0；聚焦闪烁时允许 530ms 定时器；
- 不依赖 UI 框架。

### W3：D3D12/DXGI/DComp 基础设施

- W3.2 command allocator/list、descriptor、fence；

- W3.5 透明窗口路径；
- W3.6 resize、DPI、设备丢失恢复；
- W3.7 WARP smoke test。

验收：

- 纯色清屏；
- 透明窗口无黑边；
- resize 稳定；
